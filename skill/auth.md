# Authenticated capture

Before a long capture pass, open the exact target origin using the intended
profile and engine. Confirm an authenticated page and one representative
resource load. Cookies with future expiry dates do not prove the server accepts
the session; production access does not establish access to localhost or a preview.

If access fails, inspect the landing page, new console errors and the requests
from that navigation. Compare the target's auth instance and backend with the
source session before transferring state again. Report the blocker and the
remaining coverage to the user immediately. Complete independent preparation
while waiting for any required human login.

An explicit engine is part of a saved profile's identity. Use that engine for
the login and the later capture. A different engine has a different cookie store.

Repeated redirects are a failure, not a reason to keep clicking. When the same
auth navigation repeats without progress, close that browser to stop the traffic,
then inspect its saved network and console evidence. Correct the cause before
one bounded retry. Preserve the profile or state backup before resetting storage.

For a Box, transfer saved browser state to the machine running the browser and
verify the exact Box app again. A successful state import proves the data loaded;
it does not prove the app accepted it. Read `browse help state` for state operations.

For the Upstash console, see [the console recipe](console.md) before copying an
environment or attempting preview authentication.
